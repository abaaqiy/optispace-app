# OAU building suggestions and shared campus areas

Updated 10 November 2026. The building-name dropdown contains **31 documented
academic buildings or building complexes, followed by Others**. These are suggestions;
selecting a name does not seed other buildings, create rooms, or assert that a
space is currently open for student study. Sources include university notices,
departmental addresses, university handbooks and historical venue lists. This is
not an exhaustive, surveyed inventory of every current OAU building.

Names are normalised for selection. A nickname and its descriptive name form one
option, rather than two apparent buildings. Room numbers remain in Rooms; a
complex can contain multiple rooms. For example, use **Oduduwa Hall Complex** as
the building and **Oduduwa Lecture Theatre I (ODLT I)** as a room within it.
The suggestions focus on teaching, learning, laboratories, libraries and academic
facilities. Residence halls and the Senate, Student Affairs and Students’ Union
buildings have been removed from suggestions. Existing records are not deleted or
renamed and remain editable through Others. A specific block can be selected
instead of its parent complex when its identity is known; these are not duplicate
room records, and a room must belong to only one saved building.

## Form behaviour

Search matches words anywhere in the building name, nickname or abbreviation as
the administrator types. Others stays last and remains visible during search.
Selecting it reveals **Custom building name (for Others)**. The typed value is
saved in `Building.name`; there is no second stored name column. Existing custom
names reopen under Others, and existing campus-area values remain editable on
their original record. Case-insensitive duplicate building names are rejected by
the admin form. Search uses Django's bundled Select2 with the same light/dark
palette as the room catalogue; there are no additional CDN dependencies.

## One campus area per building

`Building.campus_zone` is the sole stored campus-area value. Its searchable dropdown
retains the 16 faculty/college options and two app categories for buildings
outside those areas: **Central Campus** and **Research and Service Centres**.
Halls of Residence is no longer suggested; existing saved values remain editable.
These are app navigation categories, not an official OAU zoning
map. No faculty is inferred automatically from a building name.

Every room requires an existing building; Django admin provides its usual search
and add-related controls. The room form has no separate zone selector. The room
list still displays the inherited campus area, and the public API still returns
`zone`, so the existing frontend and zone filters continue working. Updating a
building's area updates all its rooms' displayed locations immediately on the
next request. Linked buildings are protected from deletion.

## Upgrade

Migration `rooms.0003_require_building_remove_room_zone` requires every existing
room to have a building, then makes that foreign key non-null and removes the room
zone column. If any room is unassigned, it aborts atomically and lists room codes;
assign verified buildings using the previous application version before retrying.
It never invents buildings or guesses assignments. Existing building links win
over old room-zone overrides; room IDs, codes, timetables, facilities and historical
reservation links remain intact.

Before upgrading an existing installation, back up the existing room/building data
(including old room-zone overrides), then run `python backend/manage.py migrate`.
Changing names or zones of existing buildings is an administrator decision; this
migration does not rename buildings or replace demo locations with guessed ones.
On rollback, the old room-zone column is rebuilt from the building's current zone.
Restore the pre-upgrade backup if the exact old overrides are required.
